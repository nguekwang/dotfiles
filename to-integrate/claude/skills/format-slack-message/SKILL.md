# /format-slack-message

Slackで送る「ご共有」「ご相談」メッセージを、中身のピラミッド構造(結論→根拠)はそのままに、下記の書式ルールに沿って書き直す/新規作成する。

Usage: `/format-slack-message`

## 前提: 中身を先に固める
書式を当てはめる前に、伝えたい内容を結論→根拠の構造で整理する(未整理なら`logical-thinking`のピラミッドライティングに従って先に整理する)。会話中に整理済みの文面があれば、それを流用してよい。

## 手順
1. 内容を「ご共有」項目と「ご相談」項目に分解する。
   - 判定基準(MECEな1軸):
     - ご共有: 確認だけしてほしい。結論・事実・判断はこちらで確定済みで、相手に判断を委ねない。
     - ご相談: 相手に何らかのリアクション(承認・回答・指摘等)を求める。
   - 迷ったら「相手が何もアクションを起こさなくても成立するか」で判定する。成立する→ご共有、成立しない→ご相談。
   - 件数はなるべく少なく数える: 同じ種類の確認・依頼を複数の対象(アプリ・項目等)に横並びで行うだけなら、対象の数だけ件数を増やさず1件にまとめる(対象ごとの書き方は後述の「セクション内の項目の書き方」参照)。件数を分けるのは、対象が変わっても質問の型が同じ場合ではなく、独立した別々の判断・論点が複数ある場合だけ。
2. それぞれの件数(Nご相談・Nご共有)を数える。
3. 冒頭ラベルを、件数の組み合わせから機械的に決める(MECEな1軸):
   - ご相談のみ → `【ご相談】`
   - ご共有のみ → `【ご共有】`
   - 両方 → `【ご相談とご共有】`
4. 件数テンプレ文を、ラベルと同じ組み合わせで選ぶ(文言・絵文字はそのまま使う):
   - ご相談のみ: `N点ご相談があり、ご確認いただけますと幸いです！`
   - ご共有のみ: `N点ご共有があり、ご確認いただけますと幸いです！`
   - 両方: `N点ご相談とN点ご共有があり、ご確認いただけますと幸いです！`
5. 本文を以下の順で組み立てる:
   1. `【ラベル】`
   2. 話題を一言で示す前置き(1行。例:「今回のエラーモーダルの原因について、」)
   3. 件数テンプレ文(手順4)
   4. (空行)なぜ共有・相談するに至ったかの一言(2〜3行、任意)
   5. (空行)`○ご相談` セクション(該当項目があれば)
   6. (空行)`○ご共有` セクション(該当項目があれば)
      - 両方ある場合は必ず`○ご相談`を先に置く(相手がアクションすべき論点を先に目に入れる)。
   7. 必要なら末尾に参考情報の補足セクションを置く(例:`○◯◯を元にした候補一覧 (参考)`)。ここは階層のあるリストでよく、`・大分類`→`　└　`小項目とする。

## セクション内の項目の書き方
- そのセクションの項目(=独立した判断・論点の数。手順1の「件数はなるべく少なく数える」に従った後の数)が1件のみ: 番号は振らず`・見出し`→`　└　`要点、のフラット2階層で書く。
- そのセクションの項目が2件以上: 各項目の先頭に丸数字(①②③…)を振り、丸数字を最上位に置く。丸数字の下に`　・見出し`→`　　└　`要点、と1階層深く入れ子にする(番号ぶん全体を1段下げる)。
  - 丸数字を分けるのは独立した別々の判断・論点が複数あるときだけ。同じ種類の確認を複数の対象(アプリ等)に横並びで行うだけの場合は丸数字を対象の数だけ作らず、①を1つだけ立てて対象ごとに`　・対象名`→`　　└　`想定内容、という通常通りの入れ子で並べる(ロジカルシンキングの水平関係でいう帰納的グルーピング)。
    ```
    ① 以下の想定でよろしいでしょうか！
    　・BI
    　　└　redashのレポート一覧を「施策」として出す
    　・CMS
    　　└　redashでステータスが「公開中」のコンテンツ一覧を「施策」として出す
    ```
  - `○ご共有`と`○ご相談`はそれぞれ独立に①から振り直す(セクションをまたいだ通し番号にしない)。
  - `○ご相談`の丸数字は、相手が返信で番号だけ拾って一言で答えられるようにするためのもの。論点の粒度は「①いつもの◯◯で判断」のように、相手が番号+一言(OK/NG/一言コメント)で返せる単位に揃える。
    ```
    ① いつもの、配信起動タイミングのredashと突合させて判断
    ② OK
    ③ OK
    ```
    のように番号だけで対応関係が分かる返信を想定して論点を立てる。
- `○ご共有`項目の中身は結論→背景の順(ピラミッド)を保つ。`○ご相談`項目の中身は「何を確認・判断してほしいか」→「具体的な選択肢や判断材料」の順にする。
- `○ご共有`・`○ご相談`(および末尾の参考情報セクション)の項目一覧は、セクション見出し行(`○ご共有`等)自体は素の行のまま、その下の項目の行(丸数字/`・`/`└`の行、および項目間の空行)全てにSlackの引用記法`> `を1行ずつ先頭に付ける(Slack上で引用ブロックとして視覚的にまとまるようにする)。

## 書式ルール(厳守)
- 記号は固定: セクション見出し`○`、複数項目の番号`①②③…`(丸数字)、項目`・`、補足・詳細`　└　`(全角スペース+└+全角スペース)、各セクションの項目一覧を囲むSlack引用`> `。`#`や`-`など他の記号に置き換えない。
- 丸数字を振った項目は、その配下の`・`と`└`をそれぞれ1段深く字下げする(番号なしのフラットな`・`/`└`と混在させない)。
- `・結論`・`・見出し`の直下の`└`には、その項目の中身だけを書く。他の項目の話を混ぜない(MECE)。
- 結論は根拠より先に置く(ピラミッドの縦の関係を守る)。
- 語尾は依頼・前置き文では「〜幸いです！」「〜させていただきます！」のように！を使ってよいが、結論・事実の記述文は「〜と考えられます。」「〜でした。」と句点で終える(語尾を混在させない)。
- 固有名詞・強調したい語句は「」で囲む。
- 冗長な言い回しは畳み、1論点1行を保つ。

対象のメッセージ内容・トピック(既に文面があれば貼り付ける): $ARGUMENTS
