# reference: スキル定義の詳細仕様

新規スキルを設計する際の正本。SKILL.md 雛形・補助ファイル・動的コンテキスト注入・
リポジトリ規約をまとめる。

## SKILL.md 雛形

新規 SKILL.md は以下の構成を土台にする。

```
---
name: <kebab-case-name>
description: >-
  <このスキルが解決するタスクの 1-2 文の説明。「何をするか + いつ使うか」を具体的に。>
---

# <name>

<このスキルが解決するタスクの 1-2 文の説明>

## 手順

1. <検証可能な具体ステップ>
2. <...>
3. <...>

## 補足

- <制約・注意点>
```

## 補助ファイル

- `reference.md`: 詳細仕様。SKILL.md からリンクして参照させる。
- `examples.md`: 使用例。
- `scripts/*.sh`: 実行可能スクリプト。`${CLAUDE_SKILL_DIR}` で自身のパスを参照できる。

## 動的コンテキスト注入

SKILL.md 内で `` !`<command>` `` と書くと、スキル読込時にシェルを実行し出力を埋め込む。
複数行は ```` ```! ```` ブロックを使う。skill-create の REUSE 段階はこれで既存スキル一覧を注入している。

## リポジトリ由来の規約

- 絵文字・顔文字・装飾記号を使わない。
- 技術仕様書・設計書レベルの文体。
- ファイル名は kebab-case。
- Markdown 表の区切りはハイフン 3 つ (`---`)。

## Frontmatter フィールド

すべて任意だが、`description` は自動起動を決めるため実質必須。

| Field | Role |
| --- | --- |
| `name` | 一覧での表示名。省略時はディレクトリ名。 |
| `description` | 何をするか + いつ使うか。自動起動の判定に使われる最重要フィールド。 |
| `when_to_use` | 起動条件の補足。`description` と合わせて 1,536 文字まで。 |
| `allowed-tools` | スキル有効中に確認プロンプトなしで使えるツール。例 `Read, Write, Bash`。 |
| `argument-hint` | 補完に出る引数ヒント。例 `[filename]`。 |
| `disable-model-invocation` | `true` で自動起動を無効化し、`/name` の手動専用にする。 |
| `model` | スキル有効中に使うモデル。 |

## 命名規則

- ディレクトリ名 = コマンド名。`.claude/skills/foo-bar/` は `/foo-bar` で呼ぶ。
- 厳格な kebab-case (小文字とハイフンのみ)。
- 既存ディレクトリ名と衝突させない。

## description の書き方

自動起動はこの文字列との意味的一致で決まる。

- 何をするかを述べる動詞で始める。
- いつ使うかの具体的なトリガー語・状況を入れる。
- 日本語で書いてよい。該当するなら明示的なトリガー句 (例「議事録を整形」) を含める。

悪い例: `便利なツール`
良い例: `Markdown の議事録を整形する。会議メモや文字起こしを渡されたとき、見出し・決定事項・TODO に構造化する。`

出典: 公式仕様 https://code.claude.com/docs/en/skills

## 配置

- プロジェクトスキル: `.claude/skills/<name>/SKILL.md` — このリポジトリで使うのはこちら。
- 個人スキル (全プロジェクト共通): `~/.claude/skills/<name>/SKILL.md`。
